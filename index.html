Tempo ✦ Design System
Tempo · Brite professional services

Three directions for the same product.

Tempo is where consultants log hours, PMs plan allocation, and Finance watches budget against actual. Each option below is a complete system — colour, type, spacing, and real components — in both light and dark. They differ in personality, not in completeness.

They vary by how much the interface asserts itself. Boardroom recedes: flat surfaces, navy authority, amber rationed to about one mark per screen. Daylight warms: paper instead of grey chrome, amber promoted to co-lead, friendlier curvature. Atmosphere has depth: layered surfaces, a stated light model, translucency where it earns its keep.

Switch options with the tabs above and flip the theme to judge both modes. The right choice is the one you would still want to look at on a Friday afternoon in week nine.

Tempo · Brite

Option A — Boardroom

The design language of a well-made financial instrument: navy authority, generous whitespace, and one amber accent used the way a signature is used — sparingly, and only where it counts.

Inter Tight 16px base WCAG 2.2 AA verified Light + dark, designed separately

01 — Philosophy

Calm, credible, and quiet enough to be trusted with money.

Tempo is where a consultant's Tuesday afternoon becomes a client invoice. Boardroom is built for the moment a CFO opens the utilization report and needs to believe the number — so the interface recedes, the data sits on generous white, and typography does the ranking rather than colour. Numbers are tabular everywhere; a column of hours should read as a column, not a ransom note.

The palette is Brite's own, disciplined. Blue carries every action and every link. Navy carries structure — the sidebar, the masthead, anything that frames rather than informs. Amber is rationed to roughly one mark per screen: the active nav rail, an over-cap warning, a pending-approval count. When everything is important, nothing is; Boardroom takes that literally.

Four small scales, applied without exception

Card padding is s6. Section gap is s16. Boardroom buys its calm with whitespace, so the large end of the scale is used generously and the small end sparingly.

Radius

Brite's 30px pill button is preserved exactly — pills for anything you click, rectangles for anything that holds data. That single rule keeps a dense grid readable: a timesheet cell can never be mistaken for a button.

Elevation

Shadows are navy-tinted (rgba(1,11,51,…)), never neutral grey — grey shadows on a blue-white canvas read as dirt. In dark mode shadow is nearly invisible, so elevation is carried by lightness instead: surface #101728 → raised #1A2440, with a matching hairline. Same token, different mechanism.

Motion

120ms
180ms
260ms

120ms colour and border changes (hover, focus) — must feel instantaneous. 180ms the default for anything that moves or fades. 260ms reserved for panels and drawers entering. Easing is always cubic-bezier(.2,.8,.3,1): fast out, settled in. Nothing bounces — a system that handles payroll should not be springy. All motion collapses to 1ms under prefers-reduced-motion.

06 — Components

The parts that carry the product

Every specimen below is live markup on the tokens above. Interact with them — hover a row, tab into a timesheet cell, focus a button.

Buttons

44px minimum hit height · 30px pill

One primary per view. Danger is an outlined button, not a filled red one — a filled red block in a table of approvals draws more attention than the data does, and destructive actions in a PSA are reversible-by-approval, not catastrophic. Disabled states keep their full opacity and shift to sunken + muted (5.07:1) rather than dropping to 40% alpha, which would fail contrast and read as a render bug.

Form inputs

Including error state

Errors are never colour-only. The invalid field gets a 2px border, a text message, and a glyph. Padding is reduced by 1px so the thicker border does not shift the field's height — no reflow when validation fires.

07 — Accessibility

Built in, not audited on

Focus & hit targets

  • 3px ring, offset by colour not gap. box-shadow: 0 0 0 3px rgba(58,108,233,.32) in light, a lighter blue at 40% in dark — 4.39:1 and 9.28:1 against their canvases.
  • Focus is never removed, only redirected to :focus-visible so mouse users don't see rings on click.
  • On navy the ring switches to amber with a navy spacer ring, because blue-on-navy is unreadable. This is the one place amber is mandatory rather than decorative.
  • 44 × 44 minimum for every interactive target, including the 38px-tall timesheet cell — its row padding brings the real target to 58px.
  • Timesheet cells are a roving tab order: Tab moves across the week, Enter drops to the next project row. Arrow keys move cell to cell. No mouse required to fill a week.

Colour-blind-safe status

  • No status is ever colour alone. Every status carries a glyph, and Draft additionally carries a dashed outline — the four badge types stay distinct in greyscale and under deuteranopia, protanopia and tritanopia.
  • Success/danger are not a red-green pair by shape. Approved is a check inside a filled disc; Rejected is a cross inside a filled disc; the glyph does the work if the hue collapses.
  • Over-allocation uses a diagonal hatch plus a hard capacity marker, so the overflow segment is identifiable by texture and position even in monochrome.
  • Budget bars pair colour with a baseline marker — "past the line" is a geometric fact, not a colour judgement.
  • Numeric sign is always printed (−13.8%), never conveyed by red alone.

Structure & assistive tech

  • Invalid inputs use aria-invalid="true" and aria-describedby pointing at the visible error text — screen readers get the same sentence sighted users get.
  • Every timesheet cell has an explicit aria-label naming the day and the project, because "8" in a grid is meaningless out of context.
  • Weekly and daily totals are live regions: recalculating on entry announces the new total without stealing focus.
  • The active nav item carries aria-current="page"; the amber rail is the visual echo of that state, not its only carrier.
  • Body text sits at 16px / 1.625 and the layout survives 200% zoom and 400% reflow — every wide element (timesheet grid, project table, contrast table) scrolls inside its own container, never the page.
  • prefers-reduced-motion: reduce collapses all transitions to 1ms and stops the motion specimen entirely.
Tempo Design System · Option B

Daylight

A PSA that feels like the lights just came on. Amber leads with the blue, not behind it.

01

Design philosophy

Timesheets are the most-resented ten minutes of a consultant's week. Daylight is built for the person who has to open Tempo on a Friday afternoon: warm paper instead of grey chrome, generous curvature, and Brite's amber promoted from a logo sparkle to a genuine co-lead — it carries hover, focus, progress and celebration, while the blue keeps its job as structure and commitment.

The warmth is disciplined, not decorative. Every neutral is tinted toward the same ochre so surfaces feel lit rather than beige; every shadow is brown rather than black. Finance still gets tabular figures, hard status semantics and a table that reads like a ledger — it is approachable software that never asks to be taken less seriously.

Who it's for: consultants logging daily (the primary weight of use), with PM, Finance and HR views layered on the same warm chassis. If a screen has to be used every single day, it should not feel like a compliance form.

Accessibility notes

Focus & keyboard

  • A single :focus-visible rule: 3px solid ring, 2px offset. Light mode rings in brand blue (4.37:1 on canvas); dark mode rings in #FFD34D (12.89:1) because blue on navy is too quiet to find.
  • Ring colour never matches the component it surrounds — the amber "Submit week" button gets the blue ring, blue controls get the amber one on dark.
  • Timesheet cells additionally change fill on focus, so a keyboard user tabbing across Mon→Sun leaves a visible warm trail; focus is never communicated by the ring alone.
  • Tab order follows the week left-to-right, then row-to-row. Cells accept 1–24 and decimals; arrow keys move between days.

Hit targets & density

  • Minimum interactive height 44px — buttons, inputs, timesheet cells, nav items. Compact buttons drop to 36px only in dense toolbars with ≥8px separation.
  • Nav items are full-width pills, not text links, so the target is the row.
  • Table row actions sit in a 44px cell; hover-only affordances are avoided — everything reachable by hover is reachable by tab.
  • Body copy never below 12.5px; numeric data never below 13px.

Atmosphere.

Where the other options are flat, this one has depth. Surfaces are layered and lit: luminous gradients, translucency that lets the room show through, and shadows tinted with the colour of the ground they fall on. 01 · The rule everything obeys

The light model

Glassmorphism fails when every surface invents its own lighting. Atmosphere states the model once and never contradicts it. If you are adding a component and unsure what shadow to give it, this section is the answer.

Key at 315° · elevation ≈ 60°

One soft key light sits above and to the left of the viewport — 315°, roughly 60° elevation, wide and diffuse like a north-facing window rather than a point lamp; every gradient, highlight and shadow in Tempo is derived from it.

1
Direction. Surface gradients run at 158deg — lightest at the top-left corner, coolest at the bottom-right. Drop shadows offset down and very slightly right. Nothing in the system casts a shadow upward.
2
Elevation. Height is expressed twice, never once: a top-edge inset highlight (the lit rim) plus a drop shadow that grows in blur and offset. Opacity alone is forbidden — an opacity-only ramp reads as dimming, not lifting.
3
Intensity. In light mode the rim highlight is a constant white and the shadow does the work. In dark mode it inverts: the rim brightens 5% → 18% up the ramp, because in a dark room a higher object catches more light.
4
Colour of shadow. Shadows are navy rgba(20,36,87,·) in light and near-black rgba(2,5,18,·) in dark, and above level 4 they gain a blue ambient bloom. Grey shadows on a blue ground read as dirt.
5
Legibility is not negotiable. The sheen overlay sits below content and stops at 44% height. No text ever crosses a blur boundary or a gradient stop it was not measured against. See section 09.

Try the theme toggle. Dark is where this direction lives; light is a genuinely luminous treatment — a bright room with the same window in it — not a washed-out inversion of the dark tokens.

07 · Accessibility

How depth stays usable

Built in

  • Focus rings that survive glass. A single-colour ring disappears the moment it crosses a gradient. --ring is two concentric 2px rings — a white/near-black inner and a brand outer — so one of them always contrasts, whatever is behind. Tab through the buttons and timesheet cells to see it.
  • Hit targets. 42px default, 44px minimum on inputs and day cells, 46px under pointer: coarse and below 640px. Icon-only buttons are square at full button height and always carry an aria-label.
  • Never hue alone. Status badges pair colour with a glyph and a border treatment; over-allocation adds a diagonal hatch; errors add an icon and a heavier border; disabled state removes depth entirely. Print or desaturate any screen and it still parses.
  • Text never rides a blur boundary. The sheen overlay stops at 44% height and sits below content; blurred surfaces always sit on an alpha floor of .86 or higher; and alpha rises with elevation, so the text-densest surfaces are the least see-through.
  • Wide things scroll themselves. The timesheet grid and both tables live in overflow-x containers with tabindex="0" and a group label, so keyboard users can scroll them. The page itself never scrolls sideways.

Fallbacks

Blur is a genuine cost — vestibular discomfort for some, compositor load on low-end hardware, and a hard failure on browsers without backdrop-filter. All three fallbacks replace tokens, not components, so nothing can be left behind when a new component is added later.

  • prefers-reduced-transparency — the light field is removed, every gradient token is swapped for its --solid-* equivalent, the sheen becomes none, and all blur is switched off. The elevation ramp survives, because shadow is not transparency; the layout is unchanged; contrast goes up, never down.
  • prefers-reduced-motion — hover lift is removed and every transition and animation collapses to effectively zero. Depth is a static property in this system, so the hierarchy survives untouched; the light field never moved in the first place.
  • @supports not (backdrop-filter) — translucent surfaces become opaque rather than merely unblurred, because a translucent surface with no blur behind it is the least readable state of all.
  • forced-colors — shadows drop away and every surface gains a CanvasText border, so the depth hierarchy is restated as outlines. Focus becomes a 3px Highlight outline.
  • Performance budget. Backdrop blur is permitted on seven element classes only — card shell, table shell and its sticky header, sidebar, topbar, popover, modal and its scrim. Rows, cells, badges and buttons use translucency without blur, which costs nothing.

The honest limitation: on a very long page, dozens of blurred cards will cost more than a flat option would. Atmosphere is worth choosing if depth is doing work — separating a sticky header from scrolling rows, keeping a modal in context, showing what is clickable. If the answer is "it just looks nicer", pick a flatter option and spend the frames elsewhere.
